# 解析計画

## 目的と範囲

Go2に標準搭載されている既存の純正モーターを対象に、ID変更の入口、通信方式、コマンド形式、受理条件、保存と復帰の仕組みを特定します。GO-M8010-6、A1、B1の方式をGo2にそのまま適用せず、機種・純正ファームウェアへの適合性を別々に記録します。

今回は初期設定と解析計画、公開コードから分かる初期調査までを行います。実機への送信、ID変更、ファームウェア更新、カスタムファームウェアのビルド・導入は対象外です。

## 調査順序と成果物

| 優先度 | 作業 | 主な対象 | 成果物・判定基準 |
| --- | --- | --- | --- |
| P0 | 原本と出典を固定 | 3サブモジュール、各LICENSE | 全コミット・URL・ライセンスを記録し、原本の変更がないことを検証 |
| P0 | Go2専用のID変更入口を追跡 | open SDKの `gochangeid.cpp`、CMake定義 | `GOVERSION=2` → `GO_2` → `sendRecv` → `modify_data` → `send` の呼び出し経路と行番号 |
| P0 | コマンドと通信条件を整理 | `SerialPort`、`RIS_Mode_t`、CRC関数 | RS-485、baud、8N1、フレーム長、IDビット、CRC、待機時間、復帰フレームの比較表 |
| P1 | 公式実装と照合 | 公式 `changeID.cpp`、`motor_tools/changeid`、`swboot`、`swmotor` | A1/B1方式とGo2候補の区別。必要なら既存ELFを実行せず静的解析し、通信構築部分を比較 |
| P1 | 純正Go2に適用できる条件を評価 | Go2解析資料、公開仕様、既存の通信記録 | モーター型式・ファームウェア版ごとの根拠。資料の推測とコードの事実を区別 |
| P1 | 受信と永続化の未確定事項を調査 | ACK/エラー処理、設定保存、復帰処理の静的情報 | ACK形式、旧/新IDでの応答、保存場所・タイミング、再起動後の維持、失敗時の状態を未確定一覧に記録 |
| P2 | オフライン検証を拡張 | 純粋なパケット生成・保存済みキャプチャ | シリアルデバイスを開かず、ID境界・CRC・Go1/Go2差分・応答解釈を検証 |

## 特に確認する変更条件

- 初期状態が通常モードかブートローダーモードか。`mode=7` を純正Go2が受理する根拠。
- 旧ID・新IDの有効範囲とブロードキャスト15の扱い。複数モーターに対する影響とID衝突条件。
- 使用するRS-485変換器と4 Mbaud対応、フレーム間隔、タイムアウト、再送条件。
- 変更コマンドの受理を示す応答と、正常な書き込みを証明する条件。
- 不揮発性ID設定の保存タイミング。ファームウェア更新を伴わず変更できる根拠。
- `0x04` / `0x03` の意味と復帰条件。異常終了時にブートローダーに残る可能性。

## 記録方法と完了条件

観察ごとに固定コミットのURL、パス・行番号、対象機種、関数、フレーム、根拠の強さ（コードで確認／上流の記述／未確認）を記録します。推測を確定事項として書きません。

コード上のID変更経路を特定しても、ACK・永続化・純正Go2のバージョン適合性が不明なら「実機で使える方法を確立した」とは判定しません。実機検証が必要な項目は未検証として残し、今回の解析では実行しません。

## 初期設定時の結果

3参照を取得し、元のLICENSEと固定コミットを記録しました。Go2向けの直接候補はopen SDKの `go2_changeid` です。初期調査で判明した処理と未確定事項は [initial-findings.md](initial-findings.md) を参照してください。
